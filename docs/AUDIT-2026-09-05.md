# UFIconnect Audit - September 5, 2026

## Scope and result

This is a repository-wide static/build pass, targeted HTTP regression tests,
responsive browser checks, and read-only production observations. It is not a
claim that every external integration or every historic request is fully verified.
No production accounts, payments, posts, DNS records, or deployment settings were
modified during verification. All changes belong in the audit pull request.

## Findings and fixes

| Priority | Finding | Fix / verification |
| --- | --- | --- |
| High | Auth0 could claim an existing account using only a matching email, including an unverified address. Failed provisioning could create a memory-only account. | Removed implicit email linking and volatile provisioning. Existing linked subjects still work; new accounts require durable storage. Matching-email users must sign in with their existing method. Regression tests reject both verified and unverified implicit linking. |
| High | Office controls were accessible when `OFFICE_TOKEN` was absent. | Fail closed with 503 until configured; protected endpoints remain inaccessible to guests. Updated Office's outdated comment. |
| High | Private group membership and joining could be reached by a stranger with a group ID; recommendations could expose private groups. | Check group visibility before join/member routes and recommendation selection. Tested stranger denial and public discovery. |
| High | Imported external groups could accept native UFI posts, and mobile screens still offered UFI joining. Onboarding could silently join external/private groups. | Reject native posts to external groups, hide their join buttons in native mobile lists/details/recommendations, link to the original group, and exclude external/private groups from automatic joining. |
| High | A resume draft outage looked like a successful empty draft load, risking an overwrite of the saved resume. | API returns 503; editor shows Retry and does not expose saving/exporting until the draft loads successfully. Tested at all three viewport sizes. |
| High | Uploading, selecting, or exporting a resume could unset the current primary attachment before a later write failed; concurrent updates were not serialized per account. | Use transactions and a per-user row lock for upload/selection/export; deletion takes the same lock. Failed selection rolls back, and another member's attachment cannot be selected. |
| High | Stripe subscription webhooks were acknowledged during a DB outage without persisting membership. Temporary payment failure erased the subscription link and prevented recovery. | Retryable outage responses, retain nonterminal subscription IDs, restore active plan/add-on access, keep the two subscriptions independent, and fetch current subscription state for updates. New checkout subscriptions carry tier metadata. Mocked HTTP tests cover failure, recovery, and cancellation. |
| Medium | `/users/:id` captured `/users/connections` and `/users/blocked`. | Skip the generic profile route for these static paths; both return their expected collections. |
| Medium | Partial role-settings saves replaced unrelated privacy/language settings. | Merge supplied role settings into the member's existing settings. Tests verify preservation, per-member isolation, onboarding persistence, and memory rollback after a failed DB write. |
| Medium | Malformed authentication payloads could call string functions on arrays/objects and fail instead of responding cleanly. | Validate registration/login/reset input types, normalize email/name, and return 409 for duplicate email races. |
| Medium | OAuth origin protection existed but was not used in the retry interceptor. | Canonical OAuth requests no longer switch to the Render fallback host. Public callback configuration was checked separately, without disclosing credentials. |
| Medium | Mobile session restoration expected `{profile}` while `/profile` returns the profile itself, and transient errors deleted the saved token. | Accept the actual response shape and clear credentials only on authentication rejection. Native JavaScript syntax checked; no physical-device build was run. |
| Medium | Feed filter rendering referenced an undefined `TopicChoices`. | Export/import the existing shared component and pass the canonical topic options. Static scan now checks all application JavaScript/JSX. Removed an unused dead joined-group mapping with an undefined identifier and retained its zero-count metadata. |
| Medium | Backend's explicit test list omitted the group-feed regression suite. No PR verification workflow covered these paths. | Run every `*.test.js`, add isolated real-route HTTP tests, add static checks and responsive browser tests, and wire builds/tests/screenshots into PR CI. |
| Requested | Phone was mandatory in signup and checkout. | Optional in web and native signup; supplied numbers remain validated. Blank/missing/whitespace phone inputs succeed. Stripe receives no phone field when none is saved and does not require collection at checkout. |
| Requested | Signup setup contained a reason/goals question. | Web and native onboarding now have Role, Topics, Experience. Omitted goals preserve existing saved goals; explicit goals can still be updated by preferences. |
| Requested | Home and Following only exposed two source buttons at some widths. | Six favorite-first quick sources, horizontally scrollable when needed; compact icons at tablet/phone widths. At least three fully visible buttons checked at 1440, 820, and 390 pixels. Full source menu remains available. |
| Requested | Homepage screenshot showed the old purple layout and outdated navigation. | Capture the current dark-blue Home interface using selected current public feed posts and a neutral preview member, then reference a new versioned image URL in both hero and product preview. No private member data is used. |
| Existing staged change | iOS/Android identifiers were not yet in a PR. | Preserve and include the already-staged `org.uficonnect.app` identifiers and launch-document change. No store submission was performed. |

Auth0 linking follows the need to authenticate both accounts described in
[Auth0 account linking](https://auth0.com/docs/manage-users/user-accounts/user-account-linking).
Billing recovery is grounded in
[Stripe subscription webhooks](https://docs.stripe.com/billing/subscriptions/webhooks).

## Verification

- `npm test --prefix backend`: **58 passed**, including 19 route/lifecycle checks
  and the previously omitted group-feed tests.
- `node scripts/check-js.cjs`: **115 JavaScript/JSX files** parsed with no unbound
  references across backend, web, Office, and mobile.
- Web production build: **passed**, 165 modules. Office production build:
  **passed**, 31 modules.
- `node scripts/audit-ui.mjs`: **57 responsive checks** at 1440x1000, 820x1180,
  and 390x844. Covers source visibility, Home/Following, three-step setup, blank
  phone progression, draft outage protection, video interaction overlays and
  scrolling, and navigation/overflow smoke checks for Profile, Settings,
  Connected Accounts, Command Center, Groups, Search, and Jobs.
- Browser checks use a local real-route harness with fixture feed data and a
  stubbed YouTube IFrame API. Desktop wheel scrolling and mobile touch gestures
  run in Chromium/Edge. This does **not** certify real YouTube playback or iOS
  Safari behavior. Native video framing uses an in-repo MP4.
- Backend harness blocks external network, production credentials, background
  workers, and durable file writes. SQL/Stripe tests use mocks: PostgreSQL
  concurrency, actual payment settlement, and external publishing were not run.
- Screenshots are generated under `.cache/audit-ui`; CI uploads them as an
  artifact. The homepage capture is the only generated image committed.

### Connected-account configuration

The Office credential-presence report uses `https://api.uficonnect.org` for all
callback URLs. Presence does not prove that the provider has approved the app or
that the configured credentials are valid.

- Authorization enabled by server configuration: **GitHub, GitLab, YouTube,
  Dribbble, Twitch, Bluesky**.
- Credentials absent: **X/Twitter, Facebook, Instagram, Reddit, Medium, Threads**.
  These require deployment secrets/provider approval, not invented values in code.
- **LinkedIn and TikTok** have credentials but are intentionally Coming Soon.
- Mastodon, Pinterest, Tumblr, WordPress, magazine and career-site sign-ins remain
  Coming Soon in the inspected catalog. Public content pulling is separate from
  member OAuth availability.

### Explicit limits

- No production deployment or merge is part of this PR. The existing Render
  workflow deploys `main`; review/merge is still required.
- DNS propagation by country, million-user load, backup restoration, long-run
  memory behavior, and per-source transfer completeness are **not certified**.
- Provider consent/token refresh, email delivery, AI/hashtag generation, video
  generation, cross-post publication, physical-device playback, App Store signing,
  recruiter accuracy, and end-to-end external job applications require separate
  real-provider/device checks. The smoke tests do not substitute for them.
- Business billing and missing social secrets remain deployment configuration
  work. The Office token shared in conversation should be rotated separately;
  it is not committed or included in test fixtures.

## Local preview

`npm run preview:public` starts the edited frontend with a same-origin development
proxy to the **real public API**. Signing in or saving in this preview affects
the real account. Automated tests use the isolated harness instead.

To regenerate the homepage capture deliberately:
`node scripts/audit-ui.mjs --update-homepage`.
